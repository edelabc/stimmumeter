# Ziel des Projekts

Ich baue ein System, das **Stimmungsdaten der Menschen weltweit** sammelt.  
Jeder Eintrag hat:
- einen **Detail-Indikator** (z. B. „ängstlich“, „optimistisch“, „lustlos“ …),
- einen **numerischen Wert** auf einer Skala von **0–10** (Schrittweite 0,5),
- einen **Timestamp**,
- **Geodaten** (Breite/Länge).

Alle Indikatoren sind in einer Liste ähnlich zu:
- „abschreckend, abstoßend, aktiv, allwissend, angespannt, anziehend, aufmerksam, ausgeglichen, …, zuversichtlich, ängstlich, übermütig“
mit:
- **Emoji**, **Name** und einer **Hauptkategorie**:  
  - `positiv`  
  - `neutral`  
  - `negativ`

Aus allen diesen Detail-Einträgen soll eine **Live-Weltkarte** (3D-Globus, Google-Earth-ähnlich) entstehen, die **pro Ort** eine der **3 Hauptstimmungen** zeigt:
- überwiegend POSITIV
- überwiegend NEUTRAL / GEMISCHT
- überwiegend NEGATIV

Ziel:
1. Aktuelle **Live-Stimmung nach Orten** sichtbar machen (Städte, Regionen, Länder).
2. Technische Grundlage schaffen, um später **Prognosen** (Vorhersagen) zu ermöglichen.

# Vorhandene Datenstruktur (Beispiel)

## Tabelle `mood_indicators`
Enthält alle globalen Standard-Indikatoren (aus werte_liste.md und werte_liste_erweitert.md):

- `id` (PK)
- `name` (Text, z. B. "ängstlich")
- `emoji` (z. B. "😨")
- `category` (`positiv` | `neutral` | `negativ`)
- `color` (Hex)
- `min_value` (0)
- `max_value` (10)
- `step_value` (0.5)
- `user_id` (NULL = global, sonst benutzerdefiniert)

Beispiel:  
`("ängstlich", "😨", "negativ", "#ef4444", 0, 10, 0.5, NULL)`

## Tabelle `mood_entries`
Enthält die **konkreten Stimmungs-Einträge** einzelner Nutzer:

- `id` (PK)
- `user_id` (FK)
- `indicator_id` (FK auf `mood_indicators.id`)
- `value` (0–10, Schritt 0.5)
- `latitude` (float)
- `longitude` (float)
- `created_at` (Timestamp mit Zeitzone)
- optional: `geo_hash` oder `location_id` (Clustering)

# Was du als KI tun sollst

## 1. Datenmodell prüfen und ggf. verfeinern
- Validere, ob oben stehende Tabellen für:
  - **Aggregation nach Ort und Zeitfenster**
  - **Schnelle Visualisierung auf einer Karte / 3D-Globus**
  ausreichend sind.
- Schlage nur dann neue Felder vor, wenn es wirklich nötig ist (z. B. `geo_bucket`, `country_code`, `city`).

## 2. Aggregationslogik für die 3 Hauptzustände entwerfen

Definiere einen **klaren Algorithmus**, wie aus den Detail-Indikatoren ein **Stimmungsindex pro Ort** entsteht. Beispiel-Vorgabe (du darfst optimieren, aber nicht verfälschen):

1. **Zeitfenster**: z. B. letzte 15 Minuten, 1 Stunde, 24 Stunden (konfigurierbar).
2. **Räumliche Aggregation**:
   - entweder per **Geohash** (z. B. Länge 5–7)
   - oder per **Grid** (z. B. 0.05° × 0.05°)
3. **Mapping Detail → Score**:
   - `positiv`  → +1
   - `neutral`  → 0
   - `negativ`  → −1
4. **Gewichtung nach Intensität**:
   - Normiere `value` von 0–10 auf 0–1  
     `w = value / 10`
   - Für einen Eintrag `i`:  
     `score_i = base_category_score * w`
5. **Aggregierter Score pro Zelle**:
   - `mood_score = sum(score_i) / count(entries_in_cell)`
   - Wertebereich ungefähr **−1 … +1**
6. **3 Zustände ableiten**:
   - `mood_score <= -0.2`  → **NEGATIV**
   - `-0.2 < mood_score < +0.2` → **NEUTRAL / GEMISCHT**
   - `mood_score >= +0.2` → **POSITIV**
7. Zusätzlich: Anzahl der Einträge (`intensity`), um schwache vs. starke Signale zu erkennen.

**Lieferables:**
- SQL-Beispiele (z. B. PostgreSQL + PostGIS oder Supabase) für:
  - Aggregation nach Zeitfenster
  - Aggregation nach Geohash / Grid
- Eine saubere Backend-Funktion/Route, z. B.:
  - `GET /api/mood/live?time_window=15m&zoom=5`
  die JSON zurückgibt.

### Schritt 2: 3D/ WebGL aktivieren

In der Maps JS API brauchst du:
- **Vector Map Rendering** und
- **Tilt & Rotation** aktiviert. :contentReference[oaicite:1]{index=1}  

Wichtig:
- `renderingType: RenderingType.VECTOR` oder ein Map ID mit Vector + Tilt/Rotation.
- Für volle 3D-Kontrolle ggf. `tiltInteractionEnabled` und `headingInteractionEnabled`.

### Schritt 3: Grundgerüst der Karte

Ein simples HTML-Skeleton:

```html
<div id="map" style="width:100vw; height:100vh;"></div>
<script
  src="https://maps.googleapis.com/maps/api/js?key=DEIN_API_KEY&libraries=maps"
  async defer></script>
<script>
  let map;

  async function initMap() {
    const { Map, RenderingType } = await google.maps.importLibrary("maps");

    map = new Map(document.getElementById("map"), {
      center: { lat: 0, lng: 0 },
      zoom: 2,
      renderingType: RenderingType.VECTOR,
      tilt: 45,
      heading: 0,
    });

    // Hier später: Mood-Overlays / WebGLOverlayView
  }

  initMap();
</script>
Damit bekommst du bereits eine dreh- und kippbare 3D-Map (Google-Earth-Gefühl).

3️⃣ Wie die KI „ständig“ aus den Einträgen ein Live-Bild erzeugt
Gedanklich brauchst du drei Ebenen:
Rohdaten: einzelne Mood-Einträge (User → Indikator → Wert → Zeit → Ort).
Aggregations-Engine (SQL, Backend oder KI-Assistenz):
Aggregiert z. B. alle 30 Sekunden
Nach Raster / Geohash + Zeitfenster
Berechnet mood_score, state, count
Visualisierung:
Fragt nur die fertigen aggregierten Cells ab
Zeichnet sie auf der 3D-Map
Was die KI tun kann:
Dir optimierte SQL-Queries bauen, die das Aggregieren schnell machen.
Die Kategorisierung (positiv/neutral/negativ) feinjustieren.
Die Farbrampen und Legende so gestalten, dass man auf einen Blick:
sieht, wo die Stimmung kippt,
erkennt, wo wenig Daten vorhanden sind.
